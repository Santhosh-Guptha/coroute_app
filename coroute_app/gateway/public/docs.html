Overview

1. Executive Summary & Design Philosophy

CoRoute is designed as a mission-critical, high-availability convoy safety system for motorcycle groups traveling on open highways and winding mountain routes. Motorcycle communication demands sub-30ms telemetry latency, crystal-clear audio, and uncompromising safety gating, all while remaining 100% resilient to network dead zones and battery constraints.

The entire backend infrastructure operates on Oracle Cloud Infrastructure (OCI) under an enterprise, zero-cost Always Free architecture with zero compromise on security or scalability:

100% Zero-Exposure DB

Zero Direct DB Access

The Oracle Autonomous Database is completely closed to the public internet (HTTP 403 Forbidden). All transactions are proxied, rate-limited, and validated by the Gateway VM.

In-Memory Engine

Sub-30ms Telemetry

Live GPS pings and audio packets bypass disk I/O entirely. WebSockets broadcast in RAM, shielding the database from millions of high-frequency GPS writes.

Always Free

Enterprise Autonomous 26ai

Persistent user accounts, safety profiles, completed ride GPS breadcrumbs, and fleet analytics are stored securely in Oracle Autonomous Database JSON Document collections.

Security Controls Implemented in the Mobile Client:

  • Zero Database Credentials in APK: Decompiling the CoRoute APK reveals zero database addresses, passwords, or connection strings. The APK communicates solely with https://coroute.duckdns.org/api.
  • Stateless JWT Tokens: All mobile requests carry a cryptographically signed HMAC-SHA256 JWT token stored in Android's encrypted keystore (FlutterSecureStorage).
  • Bcrypt Password Hashing: Passwords are never stored or transmitted in plain text. They are hashed using bcryptjs with high cost factors before hitting the database.
  • Role-Based Access Enforcement: The Gateway validates user roles; non-admins cannot access admin audit logs or trigger convoy purges, even if they guess the endpoint.

Data Transitions

5. Application Data Flows & Lifecycle Transitions

Flow 1: Rider Onboarding & Strict Safety Profile Gating

Motorcycle safety requires reliable rider accountability. CoRoute enforces strict profile gating:

  1. Authentication: Rider signs up with email/password or native Google Sign-In.
  2. Safety Profile Verification: The app checks if mandatory safety fields exist:
    • Verified Contact Mobile Phone
    • Full Name & Emergency (ICE) Contact Name + Phone Number
    • Bike Registration Number (or explicit toggle for Pillion Rider)
  3. Mandatory Gating: If any field is missing, the rider is directed to CompleteProfileScreen. The app strictly blocks "Join with Code" and "Plan & Lead Convoy" until safety details are saved to Oracle Database.

Flow 2: Live Convoy Telemetry (The In-Memory Highway)

How locations flow without burdening the server or battery:

  1. Adaptive Sensor Sampling: The phone's hardware GPS reports coordinates every 2.5 seconds while moving (8m filter) and drops to 30 seconds while stopped (25m filter) to preserve battery.
  2. Sub-30ms WebSocket Broadcast: Coordinates are transmitted over wss://coroute.duckdns.org/ws. The Node.js Hub processes the packet in RAM and immediately multicasts it to all riders in the convoy room.
  3. Relative Pack Math: The client computes relative pack status (Ahead, Behind, Nearby) using route projection math and displays live status chips.
  4. Zero Disk I/O: During active riding, zero database writes take place for GPS pings. Pack data stays ultra-fast and ephemeral in memory.

Flow 3: Audio Intercom & High-Priority SOS Alarm

Push-to-Talk & VOX: Audio is captured at 16 kHz (20ms frames, 640 bytes), compressed, and broadcast over the WebSocket connection to room participants.

One-Tap SOS Incident: If a rider crashes or triggers SOS:

  • An SOS packet with exact GPS coordinates is pushed at maximum priority.
  • All connected riders receive an un-dismissible HUD banner, audio alarm siren, and a one-tap "Navigate to Rider" shortcut via Google Maps.
  • The emergency incident is logged in the convoy summary record for safety audits.

Flow 4: Trip Completion & Replay Persistence

When the convoy lead taps "End Convoy":

  1. The Gateway freezes the room, compiles final distance, stops, dwell times, and rider polylines.
  2. A single consolidated trip document is written to Oracle SODA's trips collection.
  3. The convoy is archived into ended_convoys (retained for 90 days).
  4. Riders can inspect the Multi-Rider Colored Route Map, Interactive Timeline, and GPS Replay directly in their ride history.
Administration

6. Master Admin Console Architecture

CoRoute features an enterprise administration suite accessible only to designated bootstrap admins:

Fleet Analytics & Ride History

Aggregates all-time and period totals (7 days, 30 days, 1 year): total kilometers ridden, cumulative hours on the road, average group sizes, and SOS incident frequency across all finished convoys.

User Lifecycle Management

Admins can toggle rider status between ACTIVE, HOLD, BLOCKED, and DELETED. Convoy Protection prevents placing active riders on hold or deleting them while on the road.

Immediate Convoy Purge

Allows immediate administrative deletion of test or accidental convoys via DELETE /api/admin/convoys/:id/purge with automatic cascading cleanup of timeline events and track chunks.

App Version Analytics

Monitors which client builds are active in the fleet over the last 30 days, calculating whether it is safe to raise MIN_APP_BUILD without locking out active riders.

8. Ampere A1 (ARM64) Upgrade & Migration Runbook

To support thousands of concurrent riders during large motorcycle rallies, CoRoute is prepared for Oracle Cloud's Always Free Ampere A1 Flex architecture:

Current Micro Architecture

VM.Standard.E2.1.Micro

• 1/8 OCPU (AMD Burstable)
• 1 GB RAM (Uses 2 GB Disk Swap)
• 480 Mbps Network Bandwidth
• Safe Capacity: ~250 concurrent riders

Target Ampere Architecture

VM.Standard.A1.Flex

• 4 Dedicated OCPUs (Ampere Altra 3.0 GHz)
• 24 GB Physical RAM (Zero swapping!)
• 4 Gbps Network Bandwidth
• Safe Capacity: 10,000+ concurrent riders

Zero-Downtime Migration Process:
  1. Launch new instance with Canonical Ubuntu 22.04 LTS (aarch64) and shape VM.Standard.A1.Flex.
  2. Run deploy/install.sh and restore configuration from the pre-generated backup bundle.
  3. Point DuckDNS to the new IP: curl -fsS "https://www.duckdns.org/update?domains=coroute&token=...&ip=".
  4. Caddy automatically provisions a Let's Encrypt certificate on the new VM; mobile traffic switches within 60 seconds with zero data loss.
