STEPS 1–2 · PREPARE AND BACK UP

Nothing changes before a tested backup exists

Prepare

  • Lock or rotate the two admin accounts whose passwords leaked into git history
  • Copy inventory.example.env to inventory.local.env and fill in real values (never committed)
  • Create DATA_ENC_KEY and BLIND_INDEX_KEY in the Vault; same on both servers; keep an offline copy

Back up

ssh vm2 && cd /opt/coroute/gateway
node scripts/backup_export.js --set full
node scripts/backup_restore.js \
  --latest full --dry-run

Without the backup key no backup can be read. Store it in your password manager too.

09 · Prepare

Real IP addresses, Oracle account IDs and key paths live only in inventory.local.env and on the servers, never in git. The export writes an AES-256-GCM encrypted file; the restore dry run decrypts it and checks it against its manifest without writing anything.
