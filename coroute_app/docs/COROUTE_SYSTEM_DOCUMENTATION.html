CoRoute System Architecture & Complete Application Flow

CoRoute is an offline-resilient, real-time group motorcycle convoy coordination, sensor-fused telemetry radar, and emergency life-safety platform built for group expeditions through remote corridors, ghats, and high-speed expressways.

⚡ System Overview & Core Tenets

Group motorcycling presents unique challenges: intermittent connectivity, vibration, sunlight readability, gloved operation, and the high-stakes necessity of tracking stragglers without inducing rider distraction. CoRoute addresses these through five architectural pillars:

📡 Adaptive Telemetry Engine

Dynamically modulates GPS publishing between 3s (active riding >10 km/h) and 30s (stationary dwell), preserving device battery over 10-hour rides while providing tight radar resolution.

🧭 Compass Sensor Fusion

Combines GPS bearing with hardware magnetometer compass. Eliminates "spinning map" anomalies when stationary or moving under 10 km/h at hairpins and intersections.

📴 Offline-First Packet Queue

Local SQLite buffering stores location telemetry breadcrumbs when traversing mountain dead zones, automatically re-syncing in FIFO order once connectivity resumes.

🚨 Redundant Emergency Lifeline

Distress beacon alerts convoy riders in real-time while concurrently firing native intents for designated emergency phone calls, SMS with live Google Maps coordinate links, and 112 emergency dispatch.

🏛️ Technical Architecture

CoRoute operates a dual-channel client-server architecture balancing low-latency binary/JSON streaming with durable relational persistence:

Mobile Client (Flutter) Sensor Fusion + UI Layer
⇄
Node.js Gateway REST API + WS Pub/Sub
⇄
Relational Database Accounts, Convoys, Trips

Communication Channels

Channel Protocol / Port Primary Purpose Failure Mitigation
Transactional API HTTPS / REST (JWT) Registration, authentication, profile sync, convoy management, stop checkpoint persistence. Exponential backoff retry with offline request queuing for state writes.
Realtime Telemetry WSS (JSON WebSocket) Sub-second rider position broadcasts, speeds, headings, stationary statuses, SOS distress beacons. Automatic reconnect ping/pong loop (heartbeat); last-known packet retained client-side.
Voice Intercom WSS (Binary PCM / Opus) Half-duplex Push-To-Talk (PTT) radio stream for team communication without cellular phone calls. Loss-tolerant packet dropping; UI displays realtime radio channel connectivity state.

👥 Flow 2: Convoy Lifecycle (Creation, Joining & Lobby)

A convoy is an ephemeral or scheduled group ride session that synchronizes telemetry, intercom, and route checkpoints among authenticated riders.

1. Creating a Convoy

The ride leader configures the Convoy Name, Description, Speed Limit (km/h), and Stationary Dwell Threshold (1 to 30 minutes, default 3 minutes). The server allocates a 6-character unique join code (e.g. W7K2M9).

2. Joining via Code / Link

Teammates enter the join code or tap deep links (https://api.coroute.space/join/CODE). The app confirms entry, joins the group WebSocket channel, and requests convoy state.

3. Tactical Roles

Riders can be designated as LEAD (pacesetter, amber marker), SWEEPER (rear guard, electric blue marker), or MEMBER (neon cyan marker) to ensure formation integrity.

📡 Flow 3: Telemetry & Radar Engine

The heart of CoRoute is the real-time telemetry pipeline coordinated by ConvoyService and GeoService:

Hardware Sensors GPS + Compass Fusion
→
Telemetry Filter Speed & Heading Smoothing
→
Rate Controller 3s Cruising / 30s Idle
→
WebSocket Mesh All Convoy Riders

Telemetry Operational Mechanics

  • Variable Frequency Transmission: When moving (>10 km/h), telemetry broadcasts every 3 seconds. When stationary (≤10 km/h), updates drop to an idle 30-second heartbeat, dramatically cutting battery and network load.
  • Dead Reckoning & Fusion: If the vehicle is stationary or moving under 10 km/h, the GPS heading becomes erratic. CoRoute seamlessly switches to the device's hardware compass sensor (_deviceCompassHeading) for true north orientation.
  • Convoy Formation Metrics: Continuously computes:
    • Lead-to-Sweeper Gap: Haversine distance separating the ride leader from the tail sweeper.
    • Average Convoy Pace: Mean velocity across all actively moving group members.
    • Separation Warnings: Alerts if a rider falls beyond safety distance or stops unexpectedly.
  • Offline Resilience: If network connectivity drops, MemoryTrackQueue / SQLite buffers coordinates with timestamps and speeds. Upon reconnection, packets are flushed in chronological batches without dropped history.

🧭 Flow 4: Cockpit HUD & Live Map Radar

LiveCockpitMapScreen provides an ultra-high-contrast, glove-friendly heads-up display engineered for handlebars in bright sunlight or night conditions.

⚡ Oversized Telemetry HUD

Large digital speedometer with color-coded speed tier indicators (Green: Cruising, Amber: Highway, Red: Limit Exceeded), cardinal compass bearing (e.g. NW 315°), and battery percentage.

🗺️ Directional Rotating Chevrons

Teammate markers render as directional chevrons rotated to their exact compass heading (math.pi / 180.0), color-coded by role (Amber Lead, Blue Sweeper, Cyan Rider).

📴 Last Seen & Lost Rider Detection

If a rider stops transmitting for >60 seconds, their marker changes to a pin-drop icon with an amber tag showing elapsed offline time (e.g. GhostRider · last seen 4m).

🎙️ Flow 6: Half-Duplex Radio Intercom (PTT)

IntercomDock provides low-latency group voice communication using binary WebSockets, designed for Bluetooth helmet headsets (Sena, Cardo, etc.).

🔘 Push-To-Talk (PTT)

Hold-to-talk button on screen or mapped to handlebar media button. Streams microphone audio frames only while depressed to conserve battery and eliminate wind noise.

🗣️ Voice Activation (VOX)

Hands-free mode that automatically streams when speech volume exceeds a configurable decibel threshold, auto-closing after 1.5 seconds of silence.

🔀 Channel Switching

Allows broadcasting to Everyone in Convoy or toggling to a private 1-on-1 channel with Lead, Sweeper, or any individual teammate.

👤 Flow 8: Rider Profile & ICE Management

Riders manage telemetry identification and safety contacts via EditProfileScreen, accessible under the Profile section of AccountScreen.

Managed Attributes

  • Rider Mobile Number: Primary cellular phone used for team voice contacts.
  • Vehicle Category: Motorcycle (Adv), Cruiser, Sport, Commuter, Scooter, Support / Chase Car, or Other.
  • Registration Plate No: Capitalized plate number (e.g. KA 01 AB 1234) for roadside identification.
  • In-Case-of-Emergency (ICE) Name: Contact name and relationship (e.g. Spouse, Brother, Mother).
  • ICE Emergency Phone: The telephone number dialed during SOS distress triggers and receiving emergency coordinate SMS.

☁️ Cloud Infrastructure & Zero-Exposure Perimeter (403 Lockdown)

CoRoute's backend is hosted on Oracle Cloud Infrastructure (OCI) in the India South (Hyderabad) region (ap-hyderabad-1) under an enterprise, zero-cost Always Free architecture:

🖥️ OCI Compute VM (152.67.181.198)

Runs Ubuntu Linux, Caddy Edge Proxy with automated Let's Encrypt TLS 1.3, DuckDNS updater (coroute.duckdns.org), and the Node.js Gateway process daemon (port 3000). Pre-configured for migration to Always Free Ampere A1 Flex (4 OCPUs, 24 GB RAM).

🧠 Oracle Autonomous AI Database (26ai)

Serverless Autonomous Transaction Processing (ATP) with ORDS / SODA (Simple Oracle Document Access) REST API. Stores JSON Document collections for riders, convoys, trips, and ended_convoys.

🔒
Network Access Control List (ACL) Lockdown: Direct public HTTPS requests from the outside internet to the Oracle Autonomous Database URL return HTTP 403 Forbidden. Access is cryptographically and strictly restricted to the Virtual Cloud Network (coroute-vcn) and the VM Gateway IP (152.67.181.198/32). Zero external scanners or bots can reach the database login perimeter.

🛡️ Master Admin Operations, Convoy Purge & Profile Gating

The Master Admin Console provides root administrators with complete governance and safety enforcement across all fleet operations:

🗑️ Immediate Convoy Purge

Admins can permanently erase test, obsolete, or completed convoys via DELETE /api/admin/convoys/:id/purge. The Gateway automatically cascades the purge across timeline events and GPS track chunks while protecting active convoys on the road.

🚫 Rider Lifecycle & Safeguards

Admins can toggle user account states between ACTIVE, HOLD, BLOCKED, and DELETED. Active convoy protection prevents blocking or holding riders who are actively riding on the road.

📱 30-Day App Build Elevation

Audits all client build numbers reported over the last 30 days via GET /api/admin/builds. Calculates exactly how many riders would be affected before safely elevating MIN_APP_BUILD.

🛡️ Strict Registration & ICE Gating

Google Sign-In and standard registered users are required to complete full safety details (Verified Phone, Full Name, ICE Contact Name + Phone, Vehicle No / Pillion). Incomplete profiles are gated from joining or leading convoys.
